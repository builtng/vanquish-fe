1. CHECK E04 & E04 FOLLOW-UP: ONE MATCHING SCORE USING VQT'S WEIGHTS
--------------------------------------------------------------------------------
PROBLEM:
- The admin Pending Matches page (app/dashboard/pending-matches/page.jsx via
  lib/matchingAlgorithm.js) scored matches with its own hard-coded split
  (Availability 40, Modality 20, Clinical Issues 15, Demographics 15, Caseload 10),
  ignoring admin weight settings.
- VQT's agreed weights (5 Aug) are Availability 40, Modality 20, Gender 20,
  Ethnicity 10, Sexual Orientation 5, Age 5. Clinical Issues and Caseload were
  dropped from the scoring weights.
- Backend MatchScoringService previously scaled down VQT's six weights to inject
  two fixed extras (Areas of Support 15, Specialty 10).
- MatchScoringService::isExcluded used substring matching (str_contains), which
  wrongly excluded counsellors on short/partial matches (e.g., "Trauma" vs "Childhood Trauma",
  or "Eating" vs "Eating Disorders").

FIX:
  - Unified Pending Matches with backend MatchScoringService via new API endpoint:
    GET /api/pending-matches/{client}/suggestions (and POST /api/pending-matches/match).
    Pending Matches and client-facing list now show identical scores and breakdowns.
  - Adopted VQT's six weights directly from admin MatchingAlgorithmSetting:
    Availability (40), Modality (20), Gender (20), Ethnicity (10),
    Sexual Orientation (5), Age (5). Removed the fixed Areas of Support and Specialty extras.
  - Changed isExcluded to exact name matching only (trimmed, case-insensitive).
    Removed substring matching (str_contains) so partial words never exclude.
  - Updated frontend lib/matchingAlgorithm.js to mirror VQT's six weights and exact-name
    exclusion as a fallback / display engine.
  - Changing a weight in admin now dynamically updates the Pending Matches score.

TESTS VERIFIED:
  - Changing weight in admin changes Pending Matches score.
  - Pending Matches and client-facing list give identical scores for same client & counsellor.
  - Exact match in "not ready for" excludes; partial/substring match does NOT exclude.
  - Backend: MatchScoringVqtWeightsTest passed (3 tests, 20 assertions).
  - Frontend: e04-matching-sensible-results.test.mjs passed.

     - lib/api.js extracts clean, human-readable error messages from 413 and 422 responses (including Nginx/HTML 413 status pages and Laravel validation errors) instead of generic strings.
  4. Backend TC Intake support:
     - Backend tcIntake controller supports receiving pre-uploaded document URLs and individual file uploads up to 10 MB.
